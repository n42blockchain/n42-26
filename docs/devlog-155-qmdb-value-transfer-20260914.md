# QMDB 更新账户时直接转移旧值

日期：2026-09-14，接续 [devlog-154](devlog-154-qmdb-cold-operations-20260914.md)。
H2 共识、二叉树 QMDB 承诺与状态读取保持不变。**4 节点 1M TPS 尚未实测达标。**

## 找到的重复分配

`QmdbLeafTree::set_inner` 原先先读取旧账户，clone 其 `Box<[u8]>` 到 undo，
再插入新账户并释放被替换的原值。每个已存在账户或槽的更新都会额外分配、复制、
释放一次旧值；未开启 undo 时，克隆的旧值甚至立即被丢弃。

现在从 live map 移出旧 entry，将其原有 value 直接交给 `record_deactivation`，
然后按原规则撤销旧槽 active bit、追加新叶并写入新 entry。没有改变排序、槽序号、
叶/上层哈希、undo 内容和错误返回规则。live map 的临时移除只发生在同一次
`&mut self` 调用内部，且后续没有新的可恢复错误分支。

这也作用于生产 store 的候选计算、持久化提交和历史重放。store 仍检查实际根、
执行 WAL 同步并在持久化成功后发布读取版本。

## release 对照

编译改动前后的完整 core 源码，除这一处旧值转移外一致。在同一 standalone release
二进制中选择不同实现，每次启动独立进程；6 组交替执行顺序，每进程连续 3 块。
初始状态分别为 200,000 和 2,000,000 个账户，每块更新 147,000 个不同账户。
key 使用 gov5 账户键函数，value 使用真实 gov5 账户编码；这是合成账户负载，
不是实际交易回放或主网账户分布。

计时包含 node 调用方式中的 cloned iterator 收集、排序、树修改、undo 记录及根计算。
输入准备、初始状态、回滚检查和再次应用不在计时内。每块验证回滚根、append cursor、
再次应用的根及全部更新账户值；两实现的每个 generation 的根及完整序列化 undo
摘要在全部轮次一致。

| 初始账户数 | 原中位耗时 | 新中位耗时 | 耗时下降 | 原最小–最大 | 新最小–最大 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 200k | 81.231 ms | 73.954 ms | 8.96% | 75.453–92.868 ms | 69.988–86.115 ms |
| 2M | 93.153 ms | 84.315 ms | 9.49% | 86.009–110.480 ms | 78.322–94.434 ms |

每格中位数取 18 个块样本。未绑定 CPU、未隔离其他主机负载；计时开始时与节点
测试的编译/运行有重叠，所有样本原样保留，因此这些数字不是稳定延迟保证。

另外使用独立的分配计数二进制，对 200k 状态集执行相同 3 块负载。计数器转发到
System allocator，记录计时段内 alloc/alloc_zeroed/realloc 的调用和申请字节数；
**它的耗时不进入上面的时间统计**。每块少 **147,000 次分配请求、1,029,000 bytes
累计申请量**，与每个更新旧账户少复制一次的机制一致。累计申请量不是常驻内存或 RSS。

本轮测的是树更新阶段，未包含读取版本派生、WAL、EVM、网络或 H2；不能换算成整链 TPS。
前一轮的操作缓存预算也不等于本轮的分配计数。
