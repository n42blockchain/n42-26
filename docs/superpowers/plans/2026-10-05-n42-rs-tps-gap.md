# N42 Seven-Node TPS Gap Campaign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Measure a reproducible seven-node TPS gap against a frozen `../n42-rs` reference, identify N42's current end-to-end bottleneck, and prepare the first evidence-backed optimization without weakening N42 validation.

**Architecture:** Freeze both source trees, binaries, workloads, and benchmark settings before measurement. Use existing native fleet harnesses and correctness auditors to collect separate native-profile and best-effort matched-workload baselines under the shared claim protocol. Use phase/resource evidence to select one N42 optimization; write a focused follow-up design and plan for that change because its files and implementation cannot be selected responsibly before profiling.

**Tech Stack:** Rust N42 workspace, adjacent `n42-rs` workspace, existing Bash/Python seven-node runners, H2-v4, QMDB, immutable SHA-256 manifests, shared `box-claim.py` hardware arbitration.

**Spec:** `docs/superpowers/specs/2026-10-04-n42-rs-tps-gap-design.md`

## Global Constraints

- Preserve N42's H2/QC, transaction signature validation, receipt checks, QMDB state roots, persistence, and restart consistency.
- Benchmark TPS counts only transactions that were successfully committed and passed the run's chain-specific acceptance audit.
- Freeze source, binary, lockfile, genesis, validator roster, transaction stream, statistics tool, and launch-parameter hashes before a scored leg.
- Use the shared dual-path epoch claim protocol to schedule and arbitrate all builds, signatures, full audits, and node loads; do not overlap another session's work.
- Each A/B/A group changes one factor; invalidate it on competing claims, host/resource mismatch, incomplete audits, timeout certificates, or A-bookend drift above the campaign threshold.
- Do not modify `../n42-rs`; preserve its current modified and untracked files and record their hashes as part of the frozen reference.
- Do not make speculative changes to voting safety, signature checks, committee rotation, commitments, or deferred execution as throughput optimizations.
- The N42 repository already has a large uncommitted worktree; keep every change within the exact files listed in the relevant task.

## Review Focus

- Dirty or moving `n42-rs` source makes a benchmark reference ambiguous; Task 1 records full status and source hashes before builds or runs.
- Benchmark profile differences make the TPS ranking misleading; Task 2 maps workload shape, verification gates, timing windows, and success counters for both runners.
- A valid but incomplete or contaminated leg appears faster; Task 3 and Task 4 require claim/resource records and seven-node audits before summarization.
- First-window variance or A-bookend drift hides a regression; Task 4 requires the summarizer to retain first, sustained, and total windows and invalidate excessive drift.
- A microbenchmark or phase latency improvement fails to move end-to-end TPS; Task 5 requires a full-chain A/B/A gate before retaining a candidate.

## Campaign completion

The campaign completes only when valid, source-frozen reports establish the current gap and phase evidence selects the first safe optimization. This plan does not claim that a single optimization is guaranteed to close the entire gap; each later optimization gets a measured hypothesis and its own implementation/evidence gate.
