# H2-v4 trusted certificate gate — 2026-09-14

All traffic and certificates in this directory are synthetic offline fixtures.
This is not a real four-node TPS measurement. Production qualification now
requires operator-authenticated static H2-v4 configuration and verifies eight
boundary commit certificates plus their parent links to the common interval.

Reproduce with the pinned patched reth dependency from devlog 160:

```sh
cargo build --locked --offline --bin n42-keccak --bin n42-verify-commit
export N42_KECCAK_BIN="$PWD/target/debug/n42-keccak"
export N42_COMMIT_VERIFY_BIN="$PWD/target/debug/n42-verify-commit"
python3 scripts/test-h2-tps-audit.py
python3 docs/benchmarks/20260914-h2-trusted-qc-gate/run-fixture-audit.py \
  --repo "$PWD" --out /tmp/n42-trusted-qc-reproduction
```

Expected: 43 Python tests pass. The saved fixture audit counts 9/63 successful
transactions/second, with 8 real BLS verifications and 3 additional ancestry
headers. `fixture-result/trusted-config.json` is **test-only**, not a deployment
trust file. Native and Gov5 legacy signatures cannot satisfy this gate.

`h2-tps-commit-qcs.json` contains public signed requests generated by the explicitly
ignored Rust `export_tps_fixtures` test using deterministic synthetic keys. The
`signing-contexts.json` inputs permit regeneration by setting
`N42_TPS_FIXTURE_CONTEXTS` and `N42_TPS_FIXTURE_OUTPUT`, then running
`cargo test --locked --offline --bin n42-verify-commit export_tps_fixtures -- --ignored`.
No signing mode is compiled into the production verifier CLI.

Source snapshots, build/test/clippy logs, tool hashes and the complete boundary
evidence are included. The trust file's provenance, EVM execution, transaction
trie reconstruction and hardware durability are outside this gate's proof.
