# N42 总体结构、三条路线与性能基线

更新：2026-10-12。代码观察基线：`main` @ `246efcb`。
本文作为全仓路线入口；具体实现、历史测试和部署参数以链接的专项记录为准。
三条路线描述产品与验收边界，目前不代表已经存在三个独立且全部验收通过的 Git 分支。

研究选题见 [两个硕士课题：共享执行与 QMDB 可信持续运行（HTML）](research/two-master-theses-20261012.html)，综合三个工程与截至 2026-10-12 核对的研究，给出创新假设、实验协议和阶段交付。

上游适配进度见 [Reth v2.7.0 两工程稳定版适配补全](reth-stable-completion-20261012.md)，区分已升级主线与旧 chain94 兼容分支的验证状态。

## 1. 路线总览

| 路线 | 目标 | 协议与状态 | 执行与部署 | 当前边界 |
| --- | --- | --- | --- | --- |
| 自定义链兼容主线 | 与 Gov5、n42-rs 协议兼容并互通 | H2 共识；QMDB bin 二叉状态树；兼容 ETH ECDSA（secp256k1）交易、区块与 QC 契约 | 7 个或更多验证者；直接转账与解释器备用路径 | 已有 H2/QMDB、Gov5 兼容与部分混合客户端验证；七节点混合一小时与正常停机／重启恢复均通过；各窗口绑定冻结二进制 |
| 极限性能路线 | 在自定义链契约下提高真实提交 TPS | H2/QMDB 基础；使用 0x50 Ed25519 交易及认证帧协议配置；优化执行、状态与共识流水 | 同机多个验证者独立投票，同一块执行一次并共享结果；重点对齐 E1 | 原生类型、认证及执行参数接口已移植；队列、节点类型、原生回执及完整共享执行仍需贯通 |
| ETH EL + CL 路线 | Ethereum 执行客户端与 CL 兼容 | Ethereum 交易、区块、状态承诺及 Engine API；CL fork choice 与最终性 | 对接兼容 CL，按 Ethereum 规则执行 | 已有 Ethereum 默认 profile 和 Engine 接口；未据此认定独立 ETH EL+CL 产品已完整验收 |

Reth/revm、网络、数据库和工具可作为共用组件。每条路线应明确 genesis、协议配置、启动入口和验收数据。
自定义链使用 Reth 内部组件或 Engine 接口，并不改变其 H2/QMDB 产品定位。
原生性能主线处理实时交易、出块和提交；历史回放及 witness 不属于该路线的性能验收对象。

## 2. 自定义链：H2 + QMDB bin + 跨实现互通

最新联合检查：混合一小时 1799 块、7184 成功交易、七生产者覆盖 PASS；[混合恢复修复验收](chain94-recovery-repair-20261014.md) PASS。持续运行历史详见 [Gov5 replay v2 三工程七节点持续运行验收](chain94-three-client-soak-20261012.md)。

目标链路：ETH 兼容 ECDSA 交易 → 验签与 sender 恢复 → 有界交易池 → 构块 → 执行
→ QMDB bin 状态根 → H2 封头、投票与 QC → 提交和持久化。

| 兼容层 | 必须一致的契约 |
| --- | --- |
| 交易 | ETH 兼容交易编码、ECDSA（secp256k1）签名域与 sender 恢复、交易 hash、链 ID；按共同链配置确定支持的交易类型 |
| 区块 | H2 自定义链 header 编码/hash、区块身份及共同配置的交易根规则 |
| 状态 | QMDB bin 根、账户与 slot 编码、精确父状态版本、undo 和分叉切换 |
| 共识 | H2 消息、签名域、验证者集合、quorum、QC 和故障切换 |
| 执行 | nonce、余额、费用、gas、回执类型/顺序/状态和失败语义 |
| 网络 | ETH 兼容交易传播、H2 区块传播、同步与恢复 |

QMDB bin 状态承诺独立于交易签名类型。性能分支的 Ed25519 认证帧和交易帧二叉树
需要单独对齐协议配置。不同实现只有选择相同协议配置时才能共链；
采用相同算法或共享执行代码并不自动保证 wire 兼容。

7 节点为常用基线，扩展更多验证者时必须按实际验证者集合核对 quorum，
同时验证投票处理开销、换主、超时及同步。验证者数量与执行实例数量分别记录。

已有证据与待办：

- H2、QMDB 二叉承诺及 Gov5 兼容基础已存在；混合客户端历史记录见
  [Linux mixed fleet](devlog-141-linux-mixed-fleet-20260829.md)。
- 当前节点绑定 `EthPrimitives`，见 [node.rs](../crates/n42-node/src/node.rs)，
  与本路线 ETH ECDSA 交易定位一致。性能分支的 0x50 类型及认证 API 尚需完成节点接线。
- 最新 Gov5/n42-rs/n42-26 联合验收应覆盖同链连续出块、交易执行、QC、根、回执、重启和追块。
- [当前原生架构差距](benchmarks/20261006-current-native-architecture-gap.md)记录性能分支源码边界。
  兼容主线的历史通过记录不能替代最新提交的联合验收。

## 3. 性能路线：Ed25519 与极限 TPS

本路线使用原生 `0x50` Ed25519 交易和认证帧，追赶 n42-rs 的实时原生链路径。
它与第一条路线的 ETH ECDSA 交易配置分别维护和验收；跨实现互通须选择相同交易及帧配置。

### 3.2 追赶的结构与顺序

1. 原生 0x50 交易、认证帧贯穿队列、构块、传输和回执；计算一次 root，使用不可变引用。
2. 入队计数、字节和 in-flight 信用有界；减少复制、重复查找和背压等待。
3. 构块结果复用与统一执行 owner；同一计算机的同块执行一次，其余验证者共享已检查结果。
4. 直接批量转账；按 sender 依赖分组；nonce、余额和费用保持一致，解释器作为备用。
5. 精确父 QMDB 读视图、read set 和紧凑账户索引；减少账户读取的多层 hash probe。
6. 冻结分片输出供 root 与下一块直读；记录冲突合并与发布成本。
7. 优化封块、字段发布、QC、根计算和持久化流水；限制在途积压，避免后台任务挤占执行资源。

详细实施及回归门槛见 [原生实时链性能主线](performance-mainline-20261007.md)。
不预设参考开关必然有效，按 CPU、复制字节、账户读取、队列、seal/QC 等待和 IO 数据选择优化。

### 3.3 验收与当前验证状态

每条性能结果必须保存：源码与二进制身份、硬件/线程预算、验证者数、执行实例数、
交易负载、认证方式、树/帧协议配置、预热与正式窗口、实际墙钟分母。
分别报告 sealed/canonical、成功提交、状态可读和 durable 完成边界；
核对 QC、回执、QMDB 根、积压及恢复，并使用独占机器的重复对照。

原生移植基础快照 Rust 测试 19 项通过、4 项忽略；独立签名向量 3 项通过。
后续执行接线冻结测试发现测试代码 `.sum()` 类型推断错误，新增认证/执行接线测试尚未通过完整验证，
也没有新的整链 TPS 结果。细节见 [原生类型移植记录](benchmarks/20261008-native-primitives-port.md)。
本说明记录已发现的问题；修复和重新测试属于后续实现任务。

## 4. ETH EL + CL 路线

Ethereum 路线保持 Ethereum 交易、区块、状态根、Engine API 和 fork 规则，
由兼容 CL 驱动 fork choice 与最终性。完整验收至少包括 Engine 版本、payload 校验、
forkchoice 更新、实际 CL 联调、同步、重启及相关 fork 边界。

自定义链兼容主线的 H2/QMDB bin、性能分支的原生 0x50 Ed25519/帧承诺需要独立协议配置，
不能直接视为 Ethereum 共识网络已兼容。共用内部转换代码也不改变各路线的 wire 和状态承诺契约。

当前有 Ethereum 默认 header profile、EthPrimitives 和 Engine 接口，
本次梳理未建立独立 ETH EL+CL 分支完整验收通过的证据。

## 5. 分支与文档组织

截至本次观察，兼容、性能、QMDB 与上游升级工作已合并到 `main` @ `246efcb`。
历史 `perf/*`、`feat/*interop*` 等分支是工作记录；本页不创建或重命名分支。

建议后续采用：

- 自定义链兼容主线：保持 ETH ECDSA 交易兼容，维护 H2/QMDB 协议契约、跨实现向量与联合舰队验收。
- 性能分支：从兼容主线派生，使用 Ed25519/认证帧配置，小批提交；通用优化经过验收后回合并，交易协议改动保持显式配置边界。
- ETH EL+CL 分支：独立协议配置和联调验收，共用改动按需同步。

更新本页时，最高成绩必须附原报告与口径；已完成接口、已接入节点、已通过互通、
已取得性能数据分别标记。历史专项文档保留其当时条件，本页汇总当前路线。
