# QMDB 提交：保留第一次应用，去除成功路径上的撤销与重放

日期：2026-09-14，接续 [devlog-148](devlog-148-qmdb-read-index-cost-20260914.md)。
**4 节点 1M TPS 尚未得到实测证明，目标保持进行中。** 本批保留 H2 共识、二叉树
QMDB 状态承诺/读取、原始执行校验及 WAL 同步要求。

## 已改动的实际路径

此前 `compute_and_commit` 先计算并撤销候选，再重新应用同一批操作，最后保留第二次
生成的 undo。现在把它改为一次候选应用：根匹配且读视图/WAL frame 准备成功后，
直接将第一次应用的 undo 纳入分支历史。成功提交不再撤销和重放这批操作。
移动到其他父分支所需的历史 replay 仍保留。

`compute_candidate` 仍在返回前撤销；它不能把未提交的状态泄露给后续读者。
以下拒绝路径也在释放森林锁前撤销新应用：

- 计算根与头部承诺不一致。
- 读视图准备失败，包括缓存锁损坏。
- WAL frame 编码失败。

进入待持久化阶段后沿用原有串行提交和 WAL 失败回滚机制，只有写入及 `sync_data`
成功后才发布读视图。没有删去同步调用，也没有提前把 pending block 当成耐久记录。

读视图的冷路径随树位置一同修正：父视图未缓存时，现在从**已应用且通过根校验的
子状态**构建视图；父视图命中时仍从那个精确父版本派生。不能在树已位于子状态后，
再把它误标成父版本并重复应用操作。

## release 存储对照

采用同一份实际 store 定义和测试，提取掉无关 reth adapter/import，编译独立 release
harness。目录同步 helper 逐字复制自 `n42_jmt::snapshot::sync_parent_directory`，
仍执行相同的目录 `sync_all` 系统调用。提取后的定义/测试与完整源码逐字核对，
新旧版本及读取模块共 **48 项 release 测试通过**。

这不是完整节点 release 构建或重写的性能模型。完整源码、提取代码、读取模块、
依赖锁、运行日志和二进制哈希均保存在
[实验目录](benchmarks/20260914-qmdb-single-apply/)。harness 不包含 EVM、交易签名、
网络、H2、引擎其他检查和数据库落盘流程；因此结果只说明此存储提交路径的成本。

AMD EPYC 9B45，release + thin LTO，未固定 CPU 或隔离其他主机负载。
每个配置做 6 组交替次序对照，每次独立进程连续提交 3 块，以下中位数取每版本
18 个块样本。每块更新 147,000 个不同账户，使用真实 Gov5 账户编码。
时间包含树更新、可选读视图派生、WAL 编码、写入和 fdatasync；初始状态准备、
oracle 计算预期根及最终重启在计时外。

| 文件系统 / 状态集 / 读视图 | 原中位数 | 新中位数 | 耗时比 | 原最小–最大 | 新最小–最大 |
| --- | ---: | ---: | ---: | ---: | ---: |
| tmpfs / 200k / 关闭，归因对照 | 245.35 ms | 94.32 ms | 2.60x | 229.06–280.06 ms | 91.69–99.60 ms |
| tmpfs / 200k / 开启 | 285.93 ms | 130.69 ms | 2.19x | 267.69–295.91 ms | 126.09–140.77 ms |
| ext4 / 200k / 开启 | 296.82 ms | 140.74 ms | 2.11x | 278.13–616.26 ms | 135.34–166.51 ms |
| ext4 / 2M / 开启 | 450.23 ms | 236.66 ms | 1.90x | 423.17–526.52 ms | 212.81–320.84 ms |

tmpfs 的同步延迟不能代替磁盘延迟，故另在工作区 ext4 目录验证。每个配置内相同
generation 的二叉树根与 WAL 字节数，新旧实现和全部轮次一致；每个进程结束时重新
打开 store、验证 WAL 恢复及最终账户值。临时目录由测试自行清理。

这 147,000 是**状态更新数，不是交易数**，不得将上述耗时直接换算为整链 TPS。
本批也没有提供掉电测试、长时间 fleet 尾延迟或独立 H2 证书验证的证据。
