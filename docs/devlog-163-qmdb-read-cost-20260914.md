# QMDB 读取版本成本与未采用的索引调整

日期：2026-09-14，接续 [devlog-162](devlog-162-qmdb-prepared-candidate-20260914.md)。
**4 节点 1M 成功提交 TPS 仍未实测达标。** 本轮分解剩余存储开销，验证九种
读取索引方案；没有修改生产共识、二叉树承诺、读取路径或默认分片数量。

## 当前瓶颈的实际测量

在上一轮的真实 store harness 中加入阶段指标采集，仅测量用代码新增 WAL 编码
计时。2M 初始账户、每块 147k 更新、开启 QMDB read views、命中 prepared
candidate、实际 ext4 WAL 写入和 fsync，连续三块并在结束后重开验证最终状态。

| 阶段 | 三块中位数 | 范围 |
| --- | ---: | ---: |
| 读取版本构建 | 113.496 ms | 103.413–116.700 ms |
| WAL 编码 | 9.372 ms | 8.277–10.153 ms |
| WAL append，包含 fsync | 26.872 ms | 11.528–184.969 ms |
| 其中 fsync | 9.900 ms | 8.538–128.741 ms |

读取版本构建是稳定的大头；同时出现了单次 128.7 ms 的 fsync，不能据中位数
忽略持久化尾延迟。这只有一个进程三块，不是集群分位数，也不能用阶段中位数
相加替代总耗时。首次诊断日志也保留，但它没有记录二进制 SHA，不作为复核主表。

## 为什么没有直接换索引

所有方案均从相同的完整 32 字节键和相同值派生，只替换不可变查询索引，不改变
QMDB 二叉树计算。账户使用真实 Gov5 编码，存储保留 32 字节 inline 表示。
更新输入按键排序，与生产 normalization/import 的输入一致。

- `OrdMap` 的首次 2M 账户试验将更新从 116.7 ms 降到约 64 ms，但单线程读取
  从 492 ms 增到 692 ms；256 分片的有序表也有类似回退，未采用。
- 现有 HashMap 改用 Alloy 默认哈希器，首次更新约 110 ms，收益较小。
  按哈希路径排序的另一次试验约改善 4%，与该哈希器组合反而回退，未采用。
  这些是单次探索数据，不能视为稳定性能结论。
- 保留原随机哈希器，分别试验 256、1024、4096 分片。前两者在首次 2M 账户
  试验中读取回退；4096 分片在大状态表现较好，进一步做了交替顺序的重复测试。

原 64 分片与 4096 分片各测六个独立进程；每进程一次 147k 更新和各一次
单线程、16 线程读取，总计每次读取 1M 条。表内为中位数，单位 ms：

| 状态/值类型 | 更新：64 → 4096 | 单线程读取：64 → 4096 | 16 线程读取：64 → 4096 |
| --- | ---: | ---: | ---: |
| 200k 账户 | 33.360 → 39.533 | 244.051 → 250.471 | 29.159 → 27.799 |
| 2M 账户 | 103.644 → 79.304 | 480.555 → 437.403 | 38.571 → 34.555 |
| 200k 存储 | 35.984 → 41.272 | 231.825 → 243.534 | 28.139 → 27.637 |
| 2M 存储 | 102.846 → 78.004 | 459.404 → 417.349 | 37.552 → 34.933 |

大状态更新约快 24%，但小状态更新慢 15–19%，单线程读取也略慢。稀疏更新继续
测三组交替进程：只更新一个账户，200k 状态从 11 μs 增到 60 μs，2M 从
14 μs 增到 102 μs；更新 1000 条时分别是 1.637 → 1.627 ms、
3.052 → 2.143 ms。它不是全面改善，不能只挑 2M 大块成绩修改默认值。
更多分片还增加每个版本的顶层 Vec 与 Arc 复制成本；本轮未测 RSS 或长期多版本占用。

## 验证、复现与下一步

九个索引模块分别通过现有的编码、版本隔离及与二叉树/独立顺序更新的逐键比对。
完整 standalone suite 为 42 passed、10 ignored；ignored 项为计时入口。
计时不是正确性测试的替代品：计时函数只抽查前后值，逐键 oracle 在独立测试中运行。
生产文件哈希未改变，因此没有重跑无关的全节点构建。

[证据目录](benchmarks/20260914-qmdb-read-cost/)保留源码、确定性变体生成器、
固定 core 源码、依赖锁、原始日志、全部样本及每轮二进制 SHA。测量时没有并行编译，
未独占宿主机、未绑核。读取吞吐和 147k 状态更新都不能冒充执行或提交 TPS。

下一步优先验证普通 import 能否将不可变读取索引派生与候选树应用重叠，缩短当前
串行路径。必须保持精确父版本、完整 delta、根校验、WAL 后发布和失败回滚；缺少
父读取版本时保留从已验证树重建的路径。线程资源和锁依赖也需验证，避免将任务
放到可能等待同一 forest 锁的 EVM 全局池。prepared 命中路径没有剩余树应用可重叠，
必须单独测量，不能把普通 import 的潜在收益外推给所有块。

上游仍使用此前固定引用，没有刷新远端或修改相邻开发仓库。网络限制下仍没有
真实四节点结果，目标继续进行。
